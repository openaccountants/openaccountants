L43@P2: 1 Einleitung
L44@P2: 1.1 Zweck
L45@P2: Dieses Dokument enthält Zusatzspezifikationen in Bezug auf das Country-by-Country
L46@P2: Reporting (CbC) in Liechtenstein. Diese Zusatzspezifikationen sind für liechtensteinische
L47@P2: Finanzinstitute zwingend einzuhalten und umzusetzen. Sämtliche CbC-Meldungen die an
L48@P2: die Steuerverwaltung ab November 2020 übermittelt werden, müssen ausnahmslos mit
L49@P2: der XML-Schema-Version 2.0 übermittelt werden.
L50@P2: 2 XML Meldung an die STV
L51@P2: 2.1 XSD Schema Files
L52@P2: Die Meldungen sind jeweils entsprechend der aktuellen Version der XSD Schema-Files zu
L53@P2: erstellen. Diese können über die Homepage der STV oder über die Homepage der OECD
L54@P2: heruntergeladen werden.
L55@P2: Weiters gilt folgendes unbedingt zu beachten:
L56@P2: • Die Namespaces sind gemäss dem Schema-File einzuhalten
L57@P2: • Das XML File ist UTF-8 konform (Header)
L58@P2: • Die Location des Schemafiles muss wie folgt im XML angegeben werden:
L59@P2: xsi:schemaLocation="urn:oecd:ties:cbc:v2 CbcXML_v2.0.xsd"
L60@P2: 2.2 CbC User Guide
L61@P2: Der jeweils aktuelle CbC-User Guide der OECD sowie diese Zusatzspezifikation sind einzuhalten.
L62@P2: Diese können über die Homepage der STV heruntergeladen werden:
L63@P2: www.stv.llv.li  Internationales Steuerrecht  CbC-Reporting
L64@P2: 2.3 MessageSpec
L65@P2: 2.3.1 ReceivingCountry
L66@P2: Das Feld ReceivingCountry wird mit dem Wert (2-stelliger ISO Code) des endgültigen
L67@P2: Empfängerlandes befüllt, z.B. „DE“ für Deutschland.
L68@P2: Das Feld „Receiving Country“ kann pro CbC-Report und somit pro XML einmal oder
L69@P2-3: mehrfach vorkommen (1..∞). 4/6
L70@P3: 2.3.2 MessageRefID
L71@P3: [ABSENDERLAND][JAHR]-[MELDESTELLENNUMMER].[AUFSTEIGENDENUMMER3STELLIG]
L72@P3: Beispiel: LI2018-12345.123
L73@P3: Nach der Jahresangabe ist ein Minus als Trennzeichen zu setzen.

L98@P4: 2.4.2 DocTypeIndic
L99@P4: Der "DocTypeIndic" darf pro Meldung nur einmalig verwendet werden. Dies bedeutet, ein
L100@P4: "OECD 1" (New Data) Report darf nur neue Daten enthalten. Dasselbe gilt analog für alle
L101@P4: anderen „DocTypeIndic“ Werte. Pro Meldung kann nur 1 „DocTypeIndic“ Wert
L102@P4: vorkommen, ausgenommen der Wert „OECD0“ auf Ebene ReportingFI.
L103@P4: Zu Testzwecken können Meldungen mit den "DocTypeIndic" Werten OECD10, OECD11,
L104@P4: OECD12, und OECD13 übermittelt werden. Allfällige Testmeldungen werden von der STV
L105@P4: nicht ins Ausland übermittelt. Sie werden spätestens am Ende des laufenden Jahres
L106@P4: jeweils gelöscht.
L107@P4: Folgende Werte sind möglich:
L108@P4: • OECD0 Resend Option (nur für Ebene: ReportingFI)
L109@P4: • OECD1 New Data
L110@P4: • OECD2 Corrected Data
L111@P4: • OECD3 Deletion of Data
L112@P4: • OECD10 TEST Resend Option (nur für Ebene: ReportingFI)
L113@P4: • OECD11 New TEST Data
L114@P4: • OECD12 Corrected TEST Data
L115@P4: • OECD13 Deletion of TEST Data
L116@P4: 2.5 TIN & IN
L117@P4: Als liechtensteinische TIN (Tax Identification Number) bzw. als liechtensteinische IN
L118@P4: (Identification Number) ist die liechtensteinische PEID Nummer zu verwenden. Die PEID
L119@P4: Nummer ist die Kurzform der liechtensteinischen HR-Nummer.
L120@P4: Aufbau HR-Nr.
L121@P4: FL - |0001.234.567 | -8
L122@P4: Fix PEID Prüfziffer
L123@P4: Die PEID Nummer ist ohne Trennzeichen zu erfassen!
L124@P4-5: Beispiel: 1234567 6/6
L125@P5: 2.6 Spezialzeichen
L126@P5: Die folgenden fünf Spezial- bzw. Sonderzeichen (siehe Spalte “Character”) dürfen nicht in
L127@P5: der XML Datei geliefert werden. Sie sind in abgeänderter Form zu übermitteln (siehe
L128@P5: Spalte “Entity Reference”).
L129@P5: Character Description Entity Reference
L130@P5: & Ampersand &amp;
L131@P5: < Less Than &lt;
L132@P5: > Greater Than &gt;
L133@P5: ' Apostrophe &apos;
L134@P5: " Quotation Mark &quot;
L135@P5: Die folgenden drei Zeichenpaare sind nicht erlaubt bzw. nicht möglich. XML Dateien,
L136@P5: welche eines dieser Zeichenpaare enthalten, werden nicht angenommen. Sie können
L137@P5: nicht an die STV übermittelt werden.
